# Data: sources, licenses, and what does/doesn't exist publicly

This document is the single source of truth for every dataset used in this
project — where it came from, its license, and any restriction that follows
from that license. **No real yard-gate imagery exists for this project** (see
`docs/limitations.md`).

## Summary table

| Field | Real public data found? | Source | License | Used for |
|---|---|---|---|---|
| General truck/vehicle imagery | Yes | COCO 2017 (val split) | CC BY 4.0 (per-image, via Flickr) | Vehicle/truck detection, real image-quality analysis |
| License plate (real, labeled) | Yes (small) | OpenALPR benchmarks | **AGPL-3.0** (repo-wide) | Local evaluation only — see restriction below |
| Cab number | No | — | — | Not evaluated on real data; out of scope for this pass |
| USDOT number | No | — | — | Synthetic only |
| Trailer ID | No | — | — | Synthetic only |
| Seal presence | No | — | — | Synthetic only, explicitly experimental |

Scarcity for USDOT numbers, trailer numbers, cab numbers and seals is a
**finding**, not an oversight: these are yard/gate-specific and carrier-side
markings that nobody has published a labeled, public dataset for. This
matches the project brief's expectation.

## 1. COCO 2017 (general truck/vehicle imagery)

- Source: https://cocodataset.org, `val2017` split, `instances_val2017.json`
  annotations.
- License: Creative Commons Attribution 4.0. COCO images are sourced from
  Flickr; each image carries its own license reference in the annotation
  file's `licenses` array (mostly CC BY 2.0/4.0, some CC BY-NC/CC0 — the
  download script records the exact per-image license and Flickr URL in
  `data_pipeline/raw/coco_trucks/manifest.jsonl` for attribution).
- Download: `python data_pipeline/download_coco_trucks.py --limit 300`
  (no account/API key required — downloads directly from
  `images.cocodataset.org`).
- Contains: real photographs with `truck` (and optionally `bus`/`car`)
  bounding boxes. Does **not** contain plates, USDOT numbers, trailer IDs,
  cab numbers, or seals — COCO has no such categories.
- Counts actually downloaded: see `data_pipeline/raw/coco_trucks/manifest.jsonl`
  and the per-source table generated by `split_by_source.py`
  (`data_pipeline/processed/split_summary.json`) — filled in after the
  download script is run (Phase 1 verification, below).

## 2. OpenALPR benchmarks (real, labeled license plates)

- Source: https://github.com/openalpr/benchmarks — 444 real CCTV/dashcam
  photos across US/EU/Brazil plates, each with a human-annotated bounding
  box and ground-truth plate string.
- **License: AGPL-3.0**, applied repo-wide (confirmed by fetching the repo's
  `LICENSE` file directly — no per-file or per-dataset override was found).
  AGPL is a strong copyleft license with network-use disclosure obligations,
  which has real implications for a company shipping a proprietary
  yard-management product.
- **Decision**: use this dataset for **local benchmarking/evaluation only**.
  - `data_pipeline/download_openalpr_benchmark.py` downloads it to
    `data_pipeline/raw/openalpr_benchmark/`, which is git-ignored — these
    images and their derived crops are never committed to this repo or
    baked into a Docker image.
  - We do not fine-tune a model we redistribute on this data.
  - If this project moves toward production, the recommendation is to
    either (a) obtain a written license/exception from the OpenALPR
    maintainers, or (b) replace this with a dataset under a permissive
    license (MIT/Apache/CC-BY) obtained via a paid annotation vendor or a
    Roboflow Universe project with a compatible license (most require a
    free API key we don't have in this environment — see "Pending" in the
    final report).
- Download: `python data_pipeline/download_openalpr_benchmark.py --region us`

## 3. Synthetic data (USDOT, trailer ID, plate text, seal)

- Location: `data_pipeline/synthetic/generate_synthetic.py` →
  `data_pipeline/raw/synthetic/` (git-ignored; regenerate with a fixed
  `--seed` for reproducibility).
- Every record's manifest row is tagged `"is_synthetic": true`. Every
  reported metric that touches this data is reported in a table labeled
  **"synthetic"**, never merged with real-data numbers.
- What it renders and why: see the module docstring in
  `generate_synthetic.py` for the exact format references (49 CFR 390.21
  for USDOT, ISO 6346 for intermodal trailer IDs) used to make the
  rendered strings plausible rather than arbitrary.
- Augmentation applied: brightness (low-light/glare simulation), Gaussian
  blur, perspective shear ("skew"), and speckle noise ("dirt") — see
  `apply_augmentation()`.
- This is a rendering/compositing generator (2D text-on-panel), not a 3D
  renderer — it cannot simulate real camera optics, real material
  reflectance, or real mud/dirt occlusion patterns. That gap is exactly why
  synthetic and real metrics must never be blended (see
  `docs/feasibility.md`).

## 4. Format references (used by `common/validators.py` and the synthetic generator)

- **USDOT number**: 49 CFR § 390.21(b)(2), fetched directly from
  govinfo.gov (`CFR-2024-title49-vol5-sec390-21.xml`): "The identification
  number issued by FMCSA to the motor carrier or intermodal equipment
  provider, preceded by the letters 'USDOT.'" The regulation does not
  specify a digit count. We validate 5-8 digits as a permissive range based
  on FMCSA's observable public numbering (informal, not a cited spec —
  flagged as such in the validator's docstring).
- **Trailer ID / intermodal equipment**: ISO 6346 defines the container/
  chassis identification format (4-letter prefix + 6-digit serial + 1
  mod-11 check digit). Domestic dry-van trailers have no public universal
  standard; carriers use their own alphanumeric schemes. Both are handled,
  the domestic case explicitly marked "unverified format" by the validator.
- **License plate**: no single national or even single-country format
  exists in the US — each state sets its own length/character rules. We
  validate only a generic alphanumeric shape and do not claim to check any
  specific state's rules.

## 5. Detector license choice

State-of-the-art real-time detectors distributed via the `ultralytics`
Python package (YOLOv5/v8/v11) are licensed **AGPL-3.0** (a commercial
license is sold separately by Ultralytics). Using that package to run or
fine-tune a detector means the AGPL applies to the code that loads it,
which has network-use disclosure implications for a company shipping a
closed-source product.

**Decision**: this prototype's detectors use **`torchvision`** (BSD-3-Clause,
fully permissive), specifically its pretrained COCO detection models, for
general vehicle/truck localization. For plate/text-region proposals we
additionally evaluate OpenCV's (Apache-2.0) classical Haar-cascade
detector. Both choices are reported honestly against their real accuracy —
this is very likely lower than a fine-tuned YOLO model would achieve. That
accuracy gap, and its cost/license tradeoff, is itself part of the
feasibility answer this project needs to give (see `docs/feasibility.md`):
if a production build adopts YOLO, budget for either an Ultralytics
commercial license or a from-scratch/Apache-licensed reimplementation
(e.g. YOLOX, Apache-2.0).
